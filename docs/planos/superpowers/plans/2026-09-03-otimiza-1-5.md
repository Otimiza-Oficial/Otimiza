#[test]
fn so_avisa_quando_a_publicada_e_maior() {
    assert_eq!(comparar("1.5.0", "1.5.0"), Comparacao::Igual);
    assert_eq!(comparar("1.5.0", "1.6.0"), Comparacao::HaVersaoNova);
    assert_eq!(comparar("1.5.0", "v1.6.0"), Comparacao::HaVersaoNova);

    assert_eq!(comparar("1.5.0", ""), Comparacao::NaoSei);
    assert_eq!(comparar("1.5.0", "sei lá"), Comparacao::NaoSei);

```rust
#[test]
fn sem_alvo_conhecido_nao_mede_contra_qualquer_um() {
    // Medir contra um alvo qualquer e apresentar como "o servidor do jogo" é
    // fabricar um número. Não descobrir é um resultado; inventar não é.
    assert!(matches!(decidir_alvo(None), AlvoDaMedida::NaoDescobri));
    assert!(matches!(
        decidir_alvo(Some("203.0.113.10:30120".into())),
        AlvoDaMedida::Servidor(_)
    ));
}

#[test]
fn perda_total_nao_se_confunde_com_nao_medido() {
    // 100% de perda é uma medição — e das mais importantes. Zero resposta por
    // falha da própria medição é outra coisa. Colapsar as duas faria o
    // produto anunciar rede destruída quando o defeito era dele.
    assert_eq!(resumir(10, 0), Perda::Medida { enviados: 10, perdidos: 10 });
    assert_eq!(resumir(0, 0), Perda::NaoMedi);
}
```

- [ ] **Step 2: Rodar e confirmar que falha**

- [ ] **Step 3: Implementar**

Mede perda, variação do tempo de resposta e o tempo em si, contra o servidor em
que o cliente está jogando. O alvo sai das conexões ativas do processo do jogo.

Regras que a tela precisa carregar:
- **Não promete melhorar.** Perda quase sempre é do provedor, do cabo, do
  Wi-Fi ou do servidor — não do PC. O produto mede e diz onde está.
- **Travamento de rede parece FPS baixo.** É a frase que justifica o recurso:
  o cliente que otimizou e não viu diferença pode estar com problema de rede,
  e este número diz isso em vez de deixá-lo achar que foi enganado.
- **Não descobrir o servidor é resultado**, e vai escrito.
